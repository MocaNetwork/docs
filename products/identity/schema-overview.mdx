title: "What are schemas"
description: "How AIR schema records work for SD-JWT credentials — the registered credential type (vct), optional Type Metadata, and the claims your issuer backend defines."
---

A **schema** in AIR is a Dashboard record that registers a credential type, so issuance and verification programs can reference it. It does not hold the credential's data. Your issuer backend decides what goes into each credential.

An SD-JWT credential type is described by four pieces:

| Piece | Where it lives | What it does |
| --- | --- | --- |
| **Schema ID** | AIR Dashboard (**Issuer → Schemas**) | Identifies the schema record. Issuance programs, verification programs, and your backend refer to it. |
| **Credential type (`vct`)** | Dashboard record and the signed credential | Names the credential type inside the signed SD-JWT. It is not the same value as the schema ID. |
| **Type Metadata (`vctJson`)** | Dashboard record, optional | Describes the credential type and its claims. It is descriptive and does not validate or generate claims. |
| **Claims and disclosure** | Your issuer backend | The schema class in the issuer service generates the claim values, sets expiry, and lists which claims the holder can disclose selectively in its `disclosureFrame`. |

## How schemas are used

- **Issuance.** An issuance program references one schema record. When AIR asks your backend to issue, it passes the `schemaId`, and your backend returns the claims for that credential type.
- **Verification.** A verification program references the same schema record. Fields a verifier requests must match the claim keys your backend issues. See [Selective disclosure](/products/identity/selective-disclosure).
- **Consistency.** Issuer and verifier teams should agree on claim names, types, and meanings. If you publish Type Metadata, keep it consistent with the claims you issue.

To register a credential type, see [Registering credential types and creating schemas](/products/identity/schema-creation).
