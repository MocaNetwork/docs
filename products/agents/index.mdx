AIR Agents gives an application a verified link between an AI agent and the person it represents, so the application can recognise the customer, apply the right benefits, and respond safely to a request made on their behalf.

## What you can build

| Capability | What it does | Guide |
| --- | --- | --- |
| Bind an agent to a user | Link an agent key to a signed-in AIR Account with a chosen scope. | [Using Agentic Identity](/products/agents/partner-agent-api) |
| Verify credentials for an agent | Run a verification program through an agent session and share the result with the receiving application. | [How it works](/products/agents/how-it-works) |
| Delegation and consent | Collect user approval before binding, name the scopes the agent may use, and let the user disconnect. | [Delegation and consent](/products/agents/delegation-and-consent) |
| Merchant checkout token | Mint a short-lived token whose audience is a supported merchant, so the agent can start checkout. | [Create a checkout session](/api-reference/agents/create-checkout-session) |

## Who it's for

- **Agent platforms and assistant builders** that need their agents to carry user-approved identity.
- **Publishers, marketplaces, and applications with agent traffic** that need to recognise which customer an agent is acting for.
- **Merchants and merchant networks** that need to check eligibility and the agent's authority before applying a member rate, offer, or benefit.
- **Identity and loyalty providers** whose users want to present existing credentials through an agent.

One organisation can fill more than one role.
