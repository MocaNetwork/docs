Agents integrate with AIR through the Agent APIs, a set of REST endpoints your backend calls. They cover binding an agent to a user's AIR Account, agent sessions, credential listing and verification, and merchant checkout tokens. Your team provides the backend services, secure key storage, the consent screen, and the user-facing flow.

Contact the AIR team for environment access, then follow the [Agent API quickstart](/agentic-identity/partner-agent-api).

## Start with identity

Start a commerce pilot with agent binding and credential verification:

1. Get the user's approval and bind the agent. See [Ask for consent before binding](/agentic-identity/delegation-and-consent#ask-for-consent-before-binding).
2. Run the receiving application's verification program for each request.
3. Share the result with the receiving application in a format it can check. See [What a verification result proves](/agentic-identity/how-it-works#what-a-verification-result-proves).

The Agent APIs return a verification result in a single call.

A partner acting as a verifier sets up programs with AIR Kit's [verification](/airkit/usage/credential/verify). Issuing credentials is an issuer's job, with its own [backend integration](/airkit/usage/credential/issuing-credentials).

## Add checkout where the journey needs it

Identity tells the merchant whom the agent represents and which benefits apply. Checkout and payment need their own integration and authority.

For a supported merchant, an agent whose key includes `commerce.checkout` can mint a short-lived checkout token. The token's audience is the merchant, which verifies it during checkout. See [Create a checkout session](/api-reference/agents/create-checkout-session).

Decide where spending limits are enforced before an agent can pay. See [Spending limits](/agentic-identity/delegation-and-consent#spending-limits).

## Not yet available

Plan your integration without these:

- Delegation credentials, user-bound proof handoff, and delegated verification.
- Verify on Behalf, meaning verification without the user in session, which is at concept stage.
- Standing payment mandates.
- Onchain audit logs for every agent action.

The [Agent APIs reference](/api-reference/agents/introduction) documents every endpoint, request, and response.

Use [Partner fit](/agentic-identity/partners) to scope the first journey with the AIR team.
