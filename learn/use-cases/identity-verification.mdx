Modern applications increasingly need to verify who their users are — for regulatory compliance, age gating, access control, and fraud prevention. Traditional identity verification requires every platform to collect, store, and protect sensitive personal data, creating liability, re-verification friction, and breach risk.

AIR Kit offers a privacy-first alternative: **issue a verifiable credential once and let users control its disclosure across partner services**. Raw source documents remain with the issuer. Encrypted credential payloads may be stored in DStorage, while users control decryption and disclosure.

## The Problem with Traditional Verification

| Traditional Approach | AIR Kit Approach |
|---------------------|-----------------|
| User submits passport / ID to every platform | User verifies once, carries credential |
| Platform stores PII — becomes a breach target | Program requests user-approved claims and optional ZK proofs |
| Re-KYC at every new service | Portable credential accepted by any verifier in the ecosystem |
| Verification takes hours to days | Credential issued instantly on KYC pass via on-demand issuance |
| GDPR / data breach liability for every platform | Minimise disclosed claims and protect any retained data |

## How It Works

<Steps>
  <Step title="User completes identity verification">
    User goes through your KYC provider (Jumio, Onfido, Persona, etc.) as normal.
  </Step>
  <Step title="Your backend issues a KYC credential">
    The moment the KYC provider sends a pass result, your server calls on-demand issuance. No user action required.
  </Step>
  <Step title="Credential lands in the user's AIR Account">
    The issuer signs the credential and encrypts it to the holder before storing it in DStorage. The user controls decryption and disclosure.
  </Step>
  <Step title="Any partner verifies the credential via ZK proof">
    Successful verification returns a Verifiable Presentation with user-approved claims and any required proof. A ZK eligibility check can avoid disclosing the underlying identity documents.
  </Step>
</Steps>

## Data disclosure

The Verification Program determines which claims are requested and whether a ZK proof is required. The example below limits disclosure to KYC status and selected claims with user approval. Other programs may request additional fields or consent-controlled CAK access to source data.

| What the Verifier Sees | What Stays Private |
|-----------------------|--------------------|
| `COMPLIANT / NON_COMPLIANT` | Full name, passport / ID number |
| Credential expiry date | Date of birth |
| KYC level (`basic` / `enhanced`) | Residential address |
| Issuer DID | Income figures, nationality |
