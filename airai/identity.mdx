AIR Identity (Agentic) is the information authority for agents. It controls how an agent
gets user data, and how it shares the right data or proof onward to the next system,
service, or agent.

<Info>
**The core question.** Can an agent safely get the user data it needs, then share the
right data or proof onward to the next system, service, or agent?
</Info>

## Two streams

### Stream 1 — Get user data

Permissioned access to context and task data. The agent calls AIR, AIR checks policy, and
only the approved fields are released.

Examples:

- preferences and profile
- loyalty status and tier
- eligibility and credentials
- travel details
- delivery address
- payment rules

A travel agent gets loyalty status and travel preferences to suggest an itinerary —
without receiving the user's full account.

### Stream 2 — Share data / proofs onward

Scoped disclosure to external systems. AIR generates proofs, attestations, or encrypted
payloads — the agent triggers the share but does not see raw data unless required.

Modes available:

- **Raw field disclosure** when required (e.g. shipping address)
- **Selective disclosure** of specific claims from a credential
- **Proof-only disclosure** (e.g. user is 18+, no date of birth shared)
- **Encrypted payload** addressed to a specific recipient
- **Signed attestation** or verifiable presentation
- **Freshness check** and **revocation check**

An agent shares a proof that the user is over 18 to a commerce store — without revealing
date of birth — so the store can sell them alcohol.

## Disclosure modes at a glance

| Mode | What the recipient sees | When to use |
| --- | --- | --- |
| Raw field disclosure | The actual field value (e.g. address). | Required by the recipient and approved by the user. |
| Selective disclosure | A subset of credential claims. | Recipient needs specific claims, not the whole credential. |
| Proof-only disclosure | A boolean claim with a verifiable proof. | Eligibility checks, age gating, KYC status. |
| Encrypted payload | An encrypted package only the recipient can open. | Multi-hop handoff through an agent that should not see contents. |
| Attestation / VP | A signed statement of claims. | Cross-platform verification, partner integrations. |
| Freshness / revocation | A status check on an existing proof. | Reuse of proofs across sessions or partners. |

## Working with credentials

AIR Identity (Agentic) composes with AIR Kit's existing credential layer. Credentials
issued through AIR Kit (loyalty, KYC, membership, eligibility) are usable as the source
for selective disclosure, attestations, and proof handoffs — without re-issuing them for
the agent context.

For the underlying credential mechanics, see
[AIR Kit credential services](/airkit/usage/credential/credentials-flow).
