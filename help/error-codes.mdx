Use this page as a lookup when the AIR Kit REST API returns a specific HTTP status, or when an SDK method rejects with an `AirKitError`. For higher-level JWT / JWKS / CORS / rate-limit guidance, see [Common issues](/help/common-issues).

## API error codes

These errors apply to the AIR Kit REST API (e.g. [Issuance API](/api-reference/issuance-api)).

| HTTP status | Likely cause | How to fix |
| --- | --- | --- |
| 400 | Missing or invalid request fields | Verify `holderDid`, `schemaId`, `expiresAt`, `data`, `iv`, `authTag`, `encryptedKey`, and `externalId` are present and correctly typed, and that the credential data matches your schema. |
| 401 | Invalid or expired Partner JWT | Verify the JWT is not expired (`exp`), the signature matches your JWKS key, `kid` in the header maps to the correct key, and `typ: "JWT"` is set. |
| 403 | Feature not enabled or schema not allowed | Confirm credential issuance is enabled for your partner account in the Developer Dashboard. Check that your `issuerDid` owns the schema. |
| 404 | Unknown issuer DID or program ID | Double-check `issuerDid` and `credentialId` values against the Developer Dashboard. |
| 409 | User consent rejected or duplicate conflict | The user has denied consent for credentials issued on their behalf, or a duplicate credential already exists for this user + schema. Dedupe before reissuing. |
| 429 | Rate limited | Back off and retry — see [Rate limiting](/help/common-issues#rate-limiting). |
| 500 | Server-side failure | Retry with exponential backoff. If persistent, check the [Status page](/help/status) or contact support. |

## SDK errors

Every `AirService` method rejects with an `AirKitError`. Each error carries a stable `code` in `"domain/reason"` form and a coarse `category`. Rely on these rather than on `err.name` or `err.message`.

### The error object

| Field | Type | Use |
| --- | --- | --- |
| `code` | `AirKitErrorCode` (string union) | Switch on it for specific handling |
| `category` | `"user"` · `"session"` · `"config"` · `"network"` · `"internal"` | Coarse handling; always keep a fallback on this |
| `message` | `string` | Developer English for logs. **Don't show it to users** — the wording may change |
| `eventId` | `string`, optional | Quote it to AIR support |
| `data` | `object`, optional | Extra detail for some codes. Today only `credential/verification-failed` sets it, to `{ status }` |
| `name` | `string` | **Deprecated.** The previous error name, kept for existing `switch (err.name)` code |

### Categories

- **`user`** — the user cancelled, rejected, or hit something the AIR UI already explained. Usually do nothing, or just stop the flow.
- **`session`** — the session or Partner JWT is no longer valid. Mint a fresh Partner JWT or sign the user in again.
- **`config`** — an integration problem, such as bad parameters, a feature that isn't enabled, or an unsupported chain. Fix the call or your Developer Dashboard settings.
- **`network`** — transient. It is safe to offer a retry.
- **`internal`** — something failed on AIR's side. Show a generic error and log `code` and `eventId`.

### Recommended handling

```ts
import { AirKitError } from "@mocanetwork/airkit";

try {
  await airService.login();
} catch (err) {
  if (!(err instanceof AirKitError)) throw err;

  if (err.code === "auth/user-cancelled") return;

  switch (err.category) {
    case "session":
      return refreshPartnerTokenAndRetry();
    case "network":
      return showRetry();
    default:
      showGenericError();
      console.error(err.code, err.eventId);
  }
}
```

<Warning>
New codes may be added in minor releases. Always fall back on `category` so an unknown `code` is still handled.
</Warning>

<Note>
`showReceiveUI()` resolves, rather than rejects, when the user closes it. The other `show*UI()` methods reject when the user closes them.
</Note>

## SDK error codes

The **Previous `name`** column is what `err.name` returned before this release, and still returns. Use it to map existing `switch (err.name)` code to the new codes.

| Code | Category | Previous `name` | Meaning |
| --- | --- | --- | --- |
| `sdk/not-initialized` | config | `NOT_INITIALIZED` | `init()` hasn't completed |
| `sdk/already-initializing` | config | `ALREADY_INITIALIZING` | `init()` called again while running |
| `sdk/not-logged-in` | session | `NOT_LOGGED_IN` | Method needs a logged-in user |

## Provider (EIP-1193) errors

`airService.provider.request(...)` rejects with a standard EIP-1193 error, so wagmi, viem, and ethers keep working unchanged.

| `code` | Meaning |
| --- | --- |
| `4001` | User rejected |
| `4100` | Unauthorized |
| `4200` | Unsupported method |
| `4900` | Disconnected |
| `4902` | Unsupported chain |
| `-32602` | Invalid params |
| `-32003` | Transaction rejected |
| `-32603` | Internal error |

## Migrating from `err.name`

`AirServiceError` and `err.name` still work, so existing code keeps running. Both are deprecated and will be removed in the next major release.

| Before | After |
| --- | --- |
| `err instanceof AirServiceError` | `err instanceof AirKitError` |
| `err.name === "USER_CANCELLED"` | `err.code === "auth/user-cancelled"` |
| `err.name === "CLIENT_ERROR"` | Switch on `err.code`, or fall back on `err.category` |
| Showing `err.message` to users | Show your own copy per `code` or `category` |

See the [release notes](/api-reference/release-notes) for the full change.
